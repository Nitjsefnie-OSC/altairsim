# AMD Am9512 Floating Point Processor (Intel 8232)

Sources:
- [1980_AMD_MOS_LSI_Data_Book.pdf](#) — the **Am9512 data sheet**, printed pp.7-91 to 7-109
  (PDF pp.310–328). The primary source.
- [Am9511A-9512FP_Processor_Manual.pdf](#) — AMD *Am9511A/Am9512 Floating Point Processor
  Manual*, Steven Cheng, © 1981, RMC-615, cited "FPM": ch.2–4 formats and algorithms (in the
  9512 format), ch.6 interface notes, ch.8 measured times (Tables 8.2, 8.4–8.6).
- [CompuPro System Support 1 Manual.pdf](#) — cited "SS-1": pp.70–72 (test program),
  pp.79–86 (Intel **8232** preliminary data sheet, corroboration only), pp.91–92 (wiring).

The **Am9512** is a 24-pin NMOS floating-point processor: single (32-bit) and double (64-bit)
precision add, subtract, multiply and divide in a format "compatible with proposed IEEE
format", plus eight data-manipulation commands. It has **no fixed-point and no derived
functions**. The bus interface is like the [Am9511A](AMD%209511A.md)'s — two ports, an
internal LIFO stack, END/SVREQ/PAUSE — but the command codes, number formats, status bits and
END polarity all differ, and it adds an **ERR** output. Intel second-sourced it as the **8232**.
Clock 2 MHz (Am9512) or 3 MHz (Am9512-1). On the
[CompuPro System Support 1](CompuPro%20System%20Support%201.md) it is the second chip the math
socket takes.

## 1. Quick reference for emulation

| Item | Value |
|---|---|
| Ports | C/D̅ = 0: data (push on write, pop on read). C/D̅ = 1: command (write), status (read) |
| Stack | 8 × 17-bit internal words: **4 single** or **2 double** precision operands (16 bytes) |
| Byte order | push **LS byte first**, MS byte last; pop gives **MS byte first** |
| Command byte | bit 7 = SRE (service request enable); bits 6–0 = operation |
| Status | bit 7 BUSY, 6 SIGN, 5 ZERO, 4 reserved, 3 D (divide exception), 2 U (underflow), 1 V (overflow), 0 reserved |
| END (pin 24) | active **HIGH**; set at completion; cleared LOW by EACK̅ low, any read or write, or RESET |
| ERR (pin 6) | active HIGH; follows the error bits; cleared by a status read or RESET |
| SVREQ (pin 5) | active HIGH; set at completion of a command with SRE = 1; cleared by SVACK̅ low, RESET, or completion of a command with SRE = 0 |
| PAUSE̅ (pin 17) | **follows CS̅** (low while CS̅ is low and RD̅/WR̅ are high); returns high when the access is done; held low until the command ends for any access while BUSY except a status read |
| RESET | high ≥ 5 CLK: stops the command, clears status to 0, initializes the stack pointer (contents may change); END, ERR and SVREQ go LOW |
| Rounding | round to nearest, ties to even (§4) |

## 2. Interface (pp.7-92, 7-93, 7-95)

Port decode (p.7-92):

| C/D̅ | RD̅ | WR̅ | Function |
|:---:|:---:|:---:|---|
| L | H | L | Push data byte into the stack |
| L | L | H | Pop data byte from the stack |
| H | H | L | Enter command |
| H | L | H | Read status |
| X | L | L | Undefined |

- **Stack** (p.7-95): "can accommodate 4 single precision quantities or 2 double precision
  quantities. Pushing more quantities than the capacity of the stack will result in loss of
  data which is usual with any LIFO stack." Operands are entered **LS byte first**; results
  are read **MS byte first**; "Reading of the stack does not alter its data; it only adjusts
  the byte pointer. If more data is popped than the capacity of the stack, the internal byte
  pointer will wrap around and older data will be read again." Single = 4 bytes, double = 8;
  "Not pushing all the bytes of a quantity will result in byte pointer misalignment."
- **Command byte** (p.7-93): bit 7 = SRE ("This bit must be a 1 if SVREQ is to go high at end
  of executing a command"); the low 7 bits select the operation. Table 1 marks bit 7 as X
  (don't care for the operation). "Operation for bit combinations not listed above is
  undefined."
- **END** (p.7-92): "A HIGH on this output indicates that execution of the current command is
  complete. This output will be cleared LOW by activating the EACK̅ input LOW or performing any
  read or write operation or device initialization using the RESET. If EACK̅ is tied LOW, the
  END output will be a pulse." Reading status while busy is allowed, but continuous reading
  can conflict with the END flip-flop.
- **ERR** (p.7-92): "goes HIGH to indicate that the current command execution resulted in an
  error condition. The error conditions are: attempt to divide by zero, exponent overflow and
  exponent underflow. The ERR output is cleared LOW on read status register operation or upon
  RESET." It "is derived from the error bits in the status register … Thus ERR output going
  HIGH may not correspond with the completion of a command."
- **SVREQ / SVACK̅** — as on the Am9511A.
- **PAUSE̅** (p.7-93): "Whenever WR̅ and RD̅ inputs are both HIGH and CS̅ is LOW, PAUSE goes LOW."
  It returns HIGH when the write has been accepted or the read data is valid. "An attempt to
  issue a new command while the current command execution is in progress is allowed. Under
  these circumstances, the PAUSE output will not go HIGH until the current command execution is
  completed" (p.7-95). Timing diagrams p.7-107 ("Operand read when Am9512 is busy") and p.7-108
  ("Command or data write when Am9512 is busy") show PAUSE̅ low until TEHPHR/TEHPHW after END
  rises. A **status read** is not held (TPPWR status = 1.5 TCY + 50 ns min, p.7-106).
- FPM 6.3: "The principal timing difference between the Am9511A and the Am9512 is that the
  PAUSE follows RD or WR in the Am9511A whereas the PAUSE follows CS in the Am9512." FPM 6.7:
  the Z80 interface needs an inverter "because the sense of the END/ERR signals are different".

## 3. Number formats (pp.7-95, 7-96; FPM ch.2, 4)

**Single precision** (32 bits):

| 31 | 30–23 | 22–0 |
|---|---|---|
| S | E, 8 bits, bias 127 | M, 23 bits, **implied 1** before bit 22 |

N = (−1)^S × 2^(E − 127) × (1.M), "provided E ≠ 0 or all 1's".

**Double precision** (64 bits):

| 63 | 62–52 | 51–0 |
|---|---|---|
| S | E, 11 bits, bias 1023 | M, 52 bits, implied 1 |

N = (−1)^S × 2^(E − 1023) × (1.M), "provided E ≠ 0 or all 1's".

- The chip "restores this implied bit internally before performing arithmetic; normalizes the
  result and strips the implied bit before returning the results to the external data bus."
- **E = 0 is zero.** The data sheet never defines denormals, infinities or NaNs (E all 1s is
  only excluded). Commands test only the exponent field: PTOS "if the TOS prior to the PTOS
  command has only its exponent field as zero, the new content of the TOS will all be zeroes";
  CHSS "If the exponent field of A is zero, all bits of R will be zeros"; POPS "only the
  exponent of the new TOS is checked for zero, if it is zero status bit Z will set to 1";
  SDIV/DDIV "If exponent field of A is zero then R = B (Divide exception)".
- Examples (p.7-97): `0 10000011 11000…0` = 28; `1 01111010 01100…0` = −0.04296875.
- Worked encodings (FPM Tables 8.2/8.5): `5 = 40A00000` / `4014000000000000`,
  `6 = 40C00000`, `0.6 = 3F19999A`, `123 = 42F60000`, `−678 = C4298000`, `−1.234 = BF9DF3B6` /
  `BFF3BE76C8B43958`.

## 4. Rounding (p.7-98, 7-99)

"The Am9512 adopts a rounding algorithm that is consistent with the Intel® standard for
floating-point arithmetic" (Palmer, Compsac 77). **Round to even**: "if the resultant number is
exactly halfway between two floating point numbers, the number is rounded to the floating point
number whose LSB of the mantissa is 0." Accumulator bits: OF, B1–Bn, G (guard), R (round),
ST (sticky — set if any 1 is shifted right past R during denormalization; zeros shift in on
left shifts).

- Addition of magnitudes: add 1 at G; then if G = R = ST = 0, set the last mantissa bit to 0.
- Subtraction of magnitudes: if more than one left shift was performed, no rounding is
  needed; otherwise round as for addition.
- Multiplication: from the normalized double-length product, G = the next bit, R = the one
  after, ST = OR of the rest; then as for addition.
- Division: G and R are the next two quotient bits; ST = 0 if and only if the remainder is 0;
  then as for addition.

The add/subtract, multiply and divide flowcharts (Figs. 1–3, pp.7-98 to 7-100; FPM Figs.
3.1–3.3) "do not necessarily reflect the exact internal sequence of the Am9512." They show:
multiply/divide set overflow/underflow status from the unbiased exponent sum or difference;
add/subtract set overflow when the exponent carries out and underflow when a normalizing left
shift takes it below 1. **What the result holds after an overflow or underflow is not
stated.**

## 5. Commands (pp.7-94, 7-100 … 7-104)

A = TOS, B = NOS before the command. Hex for SRE = 0; set bit 7 for SRE = 1.

| Mnem | Hex | Operation | Stack after | Status affected |
|---|---|---|---|---|
| CLR | 00 | clear status | unchanged | S Z D U V all 0 |
| SADD | 01 | B + A (single) | R C D undefined | S Z U V (D 0) |
| SSUB | 02 | B − A | R C D undefined | S Z U V (D 0) |
| SMUL | 03 | B × A | R C D undefined | S Z U V (D 0) |
| SDIV | 04 | B ÷ A | R C D undefined | S Z D U V |
| CHSS | 05 | −A (single) | R B C D | S Z (U V D 0) |
| PTOS | 06 | push copy of single TOS | A\* A B C | S Z (U V D 0) |
| POPS | 07 | pop single | B C D A | S Z (U V D 0) |
| XCHS | 08 | exchange single TOS and NOS | B A C D | S Z (U V D 0) |
| DADD | 29 | B + A (double) | R undefined | S Z U V (D 0) |
| DSUB | 2A | B − A | R undefined | S Z U V (D 0) |
| DMUL | 2B | B × A | R undefined | S Z U V (D 0) |
| DDIV | 2C | B ÷ A | R undefined | S Z D U V |
| CHSD | 2D | −A (double) | R B | S Z (U V D 0) |
| PTOD | 2E | push copy of double TOS | A A | S Z (U V D 0) |
| POPD | 2F | pop double | B A | S Z (U V D 0) |

- A\* (PTOS): "A\* = A if exponent field of A is not zero; A\* = 0 if exponent field of A is
  zero." The NOS is an exact copy of the old TOS.
- POPS/POPD: "The internal stack control mechanism is such that A will be written at the
  bottom of the stack." POPD "has the same effect as exchanging TOS and NOS."
- SDIV/DDIV: "If exponent field of A is zero then R = B (Divide exception)."
- CHSD: "If the double precision operand A is zero, then the sign is not affected."
- CLR: "This essentially is a no operation command as far as operands are concerned."
- Opcode bits (Table 1): single-precision commands have bits 6–4 = 000; double-precision
  commands have bits 6–4 = 010 (`0101 xxxx`).
- Intel 8232 (SS-1 pp.79–86) is the same part; where its prose differs, the AMD sheet governs.

## 6. Status register (p.7-96)

| 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |
|---|---|---|---|---|---|---|---|
| BUSY | SIGN S | ZERO Z | reserved | DIVIDE EXCEPTION D | EXPONENT UNDERFLOW U | EXPONENT OVERFLOW V | reserved |

"All the bits are initialized to zero upon reset. Also, executing a CLR (Clear Status) command
will result in all zero status register bits. A zero in Bit 7 indicates that the Am9512 is not
busy and a new command may be initiated. As soon as a new command is issued, Bit 7 becomes 1 to
indicate the device is busy and remains 1 until the command execution is complete, at which
time it will become 0. As soon as a new command is issued, status register bits 0, 1, 2, 3, 4,
5 and 6 are cleared to zero. The status bits will be set as required during the command
execution. Hence, as long as bit 7 is 1, the remainder of the status register bit indications
should not be relied upon unless the ERR occurs." "An attempt to divide by zero is the only
divide exception." Z: "the result returned to TOS after a command is all zeros." S: "the result
returned to TOS is negative."

## 8. On the CompuPro System Support 1 (SS-1 pp.70–72, 91–92)

- Same ports as the 9511A: base+8 data, base+9 command/status.
- "The ERROR signal is only available on the 9512 (8232) and the END polarity is different
  between the two types of math chips. J6 is used to correct for the polarity difference."
  The SS-1 reference §7.3 adds that ERROR reaches only jumper J7, not the slave 8259A.
- The SS-1 test program's 9512 path (p.72) is printed **without object code**, as source:

```
START:  LXI  G,GREET12      ; ⚠ "G" — must be D
        MVI  C,PSTRING
        CALL BDOS
        LXI  H,TBL3
        MVI  C,8            ;length of table into reg c
TEST2:  MOV  A,M
        OUT  DREG
        INX  H
        DCR  C
        JNZ  TEST2
        MVI  A,1            ;single precision add (SADD)
        OUT  CREG
        MVI  C,R            ; ⚠ "R" — must be 4
        LXI  H,TBL1         ; ⚠ must be TBL4
COMP2:  IN   DREG
        CMP  M
        JNZ  ERROR
        INX  H
        DCR  C
        JNZ  COMP2
        IN   CREG
        LXI  D,OKMSG
        ...
TBL3:   DB   00,00,80H,3FH,00,00,80H,3FH   ; 1.0, 1.0 (LS byte first)
TBL4:   DB   40H,00,00,00                  ; 2.0 (MS byte first)
```

  With the three fixes it pushes 1.0 twice, issues SADD, and expects `40 00 00 00`.

## Quirks worth carrying

- END is active **HIGH** (the 9511A's is active low); ERR exists only on this part.
- PAUSE̅ follows CS̅, not RD̅/WR̅ — a chip select decoder must not glitch, or the bus deadlocks
  (FPM 6.3, 6.7).
- Status bits 0–6 clear when a command is issued; only valid once BUSY = 0.
- E = 0 means zero regardless of the mantissa; there are no denormals in the documents.
- Results are rounded to nearest-even; this matches IEEE 754 round-to-nearest for normal
  results.
- ⚠ The result after exponent overflow or underflow is **not documented**. Unresolved.
- ⚠ Table 3's DSUB result has the wrong sign; ⚠ the SS-1 9512 test path has three typos (§8).
